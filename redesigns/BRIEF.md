# Portfolio redesign brief

Ten designers each build one complete, working redesign of Ben Mega's portfolio
page (benmega.com). A panel picks the three best. Ben chooses one and copies it
into the repository root.

Everyone on the team reads this file first. It is the single source of truth.

## 1. Who the page is for

Ben Mega is a **CS teacher and full-stack developer**. His line is
**"Making programming accessible"**. He builds education tools (Classroom Chat,
Auto-Prep), apps (Mega Chess, Local Chat) and a game (Fractal Defense).

Visitors, in order of importance:

1. Recruiters and hiring managers, for developer and ed-tech roles. They give
   the page under a minute. They need: who he is, proof he ships real things,
   how to reach him.
2. Schools, teachers and parents who meet his tools and want to know who made
   them.
3. Other developers who land here from GitHub.

A visitor should understand who Ben is within five seconds, reach a live
project within one click, and find contact details without hunting.

## 2. What is wrong with the current page

Look at it yourself: `index.html`, `styles.css`, `script.js` in the repository
root, and the screenshots in `redesigns/_shots/current/`.

- The hero is generic and nearly empty. The 170px photo is stretched to 256px.
- No navigation, no contact section, no closing call to action.
- Project cards are text only. The real screenshots are hidden in a lightbox.
- Tech icons on the cards are grey, unlabelled and have no accessible names.
- The skills section is HTML inside an SVG, so its text shrinks on phones.
- The floating owl has no context. Nothing says what it is.
- Light mode is an afterthought: contrast fails in several places.
- Icon-only links have no accessible names. The lightbox has no keyboard
  support. There is no `main` landmark and no meta description.
- The Local Chat "Screenshots" button is a dead `href="#"` link.
- Reveal animations are slow and leave content invisible for seconds.
- Leftover CSS and JS for a navigation bar and skill cards that no longer exist.

## 3. Deliverable

A folder `redesigns/<your-slug>/` with exactly these files:

| File | Purpose |
| --- | --- |
| `index.html` | The page |
| `styles.css` | All styles |
| `script.js` | All behaviour |
| `NOTES.md` | Concept, decisions, and notes for Ben (see section 9) |

The file names match the repository root on purpose. Promoting a design is a
plain copy of three files. So:

- Reference assets exactly as the real site does: `assets/profile.jpg`,
  `styles.css`, `script.js`. No `../`, no leading slash. The preview server
  maps `redesigns/<slug>/assets/` to the real `assets/` folder.
- No other files. No new images. Draw with CSS and inline SVG.
- **Do not change anything outside your own folder.** Not the root files, not
  `assets/`, not `scripts/`, not other designers' folders. Do not run git
  commands that change anything. Do not delete anything outside your folder.

## 4. Technical rules

- Plain HTML, CSS and vanilla JavaScript. No framework, no build step, no npm
  packages. The site is deployed by copying files to S3.
- External resources allowed: the devicon stylesheet that the site already
  uses, the three external icon images the site already uses (Gunicorn, OpenAI,
  Hugging Face), and Google Fonts (at most two families, `display=swap`, with a
  sensible fallback stack). Nothing else. No analytics, no third-party scripts.
  The page must stay usable when a CDN does not load.
- The content is in the HTML, not generated by JavaScript. With JavaScript
  turned off, everything can still be read. Hide things for a reveal animation
  only after JavaScript has started (for example under an `html.js` class).
- Animations are short. Nothing on screen stays invisible for more than about
  half a second. Respect `prefers-reduced-motion`.
- The page may be restored from the back/forward cache. Nothing may be stuck in
  a hidden or half-animated state when that happens. The current script runs
  its setup in a `pageshow` handler for this reason; setting up twice must be
  harmless.
- Keep the code the way a careful developer would hand it over: CSS custom
  properties for colours, spacing and type; no dead code; no inline event
  handlers; comments only where something is not obvious.

## 6. The screenshot galleries: a contract you must keep

A script, `scripts/update-galleries.mjs`, runs before every commit and deploy.
It finds every element that has the class `btn-gallery` and the attribute
`data-gallery-dir`, and rewrites that element's `data-images` attribute with
the image files in that folder. Your page must keep working with it.

| Project | Required on the gallery button |
| --- | --- |
| Mega Chess | `class="... btn-gallery"`, `data-title="Mega Chess Screenshots"`, `data-gallery-dir="assets/mega-chess"`, `data-images="..."` with the ten files, comma separated |
| Auto-Prep | `class="... btn-gallery"`, `data-title="Auto-Prep Screenshots"`, `data-gallery-dir="assets/auto-prep"`, `data-images=""` |
| Local Chat | `class="... btn-gallery"`, `data-title="Local Chat Screenshots"`, `data-gallery-dir="assets/local-chat"`, `data-images="assets/local-chat/app_ui_mockup.jpg,assets/local-chat/promotional_graphic.jpg"` (this fixes the dead link) |
| Fractal Defense | `class="... btn-gallery"`, `data-title="Fractal Defense Screenshots"`, `data-repo="benmega/FractalDefense"`, `data-folder="screenshots"`. No `data-gallery-dir`. On click the images are fetched from `https://api.github.com/repos/<repo>/contents/<folder>`, as the current script does. |

Rules:

- The lightbox reads `data-images` **at the moment of the click**, because the
  script changes it between deploys. Never copy the list into JavaScript.
- An empty `data-images` must look intended. Auto-Prep has no screenshots
  today and may have ten tomorrow, without anyone touching your HTML. Decide in
  JavaScript at load time: hide or disable the button while the list is empty,
  show it when it is not.
- You may show screenshots directly on the page (thumbnails, device frames,
  strips). For folders with `data-gallery-dir`, anything that must stay in sync
  with the folder has to come from `data-images`. A fixed, hand-picked image
  (for example one hero screenshot per project) may be written in the HTML.
- The lightbox works with the keyboard: Escape closes, arrow keys move, focus
  goes into it on open and back to the button on close. Images have alt text.
  It shows a counter and handles loading and failure states.
- Some screenshots are about 1 MB. Lazy-load what is not on the first screen
  (`loading="lazy"`, with `width` and `height` so the page does not jump).

## 7. Quality bar

- **Both themes are first class.** The page follows `prefers-color-scheme`.
  Light and dark are each designed, not derived. A manual toggle is optional.
- **Responsive from 360px to 1920px.** No horizontal scroll. On phones, tap
  targets are at least 44 x 44 px and text is at least 16px for body copy.
- **Accessible.** Landmarks (`header`, `nav`, `main`, `footer`), one `h1`,
  ordered headings, a skip link, visible focus styles, names on every control,
  WCAG AA contrast (4.5:1 for text, 3:1 for large text and UI).
- **Fast.** No layout shift. No heavy image on the first screen.
- **Complete head.** `lang`, viewport, title, meta description, Open Graph
  title and description, `theme-color` for both themes, the Ω favicon.
- **Looks finished.** Consistent spacing scale, deliberate type scale, aligned
  edges, real hover, focus and active states. It has to survive a designer
  looking at it closely.

## 8. How to check your work

You cannot judge a design from its source. Look at it.

```bash
node redesigns/_tools/shot.mjs <your-slug>
```

This renders four views (desktop and phone, dark and light) and writes to
`redesigns/_shots/<your-slug>/`:

- `<view>-00.png`, `-01.png`, ...: the page one screen at a time
- `<view>-full.png`: the whole page in one image
- `report.json`: automatic checks (also printed)

**Open the images with the Read tool and look at them.** Then fix what you see
and run it again. Expect to go round several times.

One view only, which is faster while you iterate:

```bash
node redesigns/_tools/shot.mjs <your-slug> --only mobile-light
```

Interactions (one image of the screen after your script ran):

```bash
node redesigns/_tools/shot.mjs <your-slug> --only desktop-dark --name gallery --eval "document.querySelector('.btn-gallery').click()"
node redesigns/_tools/shot.mjs <your-slug> --only mobile-light --name dialog --eval "document.querySelector('dialog').showModal()"
```

Add `--reduced-motion` to check that mode.

Other screen sizes, written as width x height and theme. Widths under 600 are
rendered as a phone:

```bash
node redesigns/_tools/shot.mjs <your-slug> --only 360x740-light,768x1024-dark,1024x768-light,1920x1080-dark
```

The printed report flags: horizontal scroll, text that is on screen but
invisible, broken images, console errors, failed requests, missing required
text, links and elements, dead links, stretched images, missing alt text,
controls without names, small tap targets, heading problems and low contrast.
The contrast figure is an estimate and skips text on images and gradients.
Treat every line as something to fix or to explain in NOTES.md.

Run the commands from the repository root:
`C:\Users\Ben\ProgrammingProjects\Portfolio`.
